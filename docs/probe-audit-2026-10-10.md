## Hysteria2 的可行探测路径

Hysteria2 基于 QUIC/UDP，TCPing 同一端口不能验证它。实际可用性应通过 Mihomo 带原节点参数完成认证，再经该连接请求 204、网页和下载。国内远程入口探测与 GitHub 的认证实连是两项不同证据，不能混写。[Hysteria2 协议说明](https://v2.hysteria.network/docs/developers/Protocol/)

目前找到 [idcd UDP 工具](https://www.idcd.com/tools/udp)，其公开接口允许指定国内探测点并发送自定义载荷。[机器可读接口规范](https://www.idcd.com/v1/openapi.json) 和 [在线节点列表](https://www.idcd.com/v1/nodes) 可核对协议能力；实测成都移动节点具备 UDP 能力。匿名探测仍有服务端频率限制，完整额度未公开，不能承诺不限额免费全量。

18:00—18:02 做了小规模真实远程探测，均由 idcd 国内节点发包，调用端只负责编排；没有将手机本地测速代替云端流程，也没有向第三方发送节点认证密码：

| 对照或节点 | 发包方式 | 成都移动 | 重庆电信 |
|---|---|---|---|
| 阿里 DNS，223.5.5.5:53 | 合法 DNS 查询 | 收到 61 字节回包，10.374 ms | 未测 |
| n-2e60b13ec05a，未混淆 HY2 | 1,200 字节 QUIC 保留版本请求 | 收到 35 字节回包，278.722 ms | 收到 35 字节回包，243.268 ms |
| n-1d4370f209d6，Salamander HY2 | 同类请求，按节点混淆参数封装 | 5 秒内无回应 | 5 秒内无回应 |

保留版本请求利用 QUIC 的版本协商响应，适合作为轻量可达性正向证据，不能替代 TLS、Hysteria 认证或网站请求。[QUIC 规范](https://datatracker.ietf.org/doc/html/rfc9000#section-6.3)

当前 idcd 结果只有回应标志、字节数和延迟，没有原始回包，因而本次不能核验回包是否为合法 QUIC 版本协商包；有 UDP 回应只能记录为国内 UDP 可达证据，不能标记完整协议握手已通过。无回应也不能直接判为不通：可能有过滤、丢包、混淆兼容问题或服务不响应此类探测。

两份证据也说明入口可达与实际代理质量必须分别检查：未混淆样本在只读云端诊断中 204 仅 1/3 通过；混淆样本 204 为 3/3，通过 Google/YouTube，但 Reddit 未通过。即使今后国内 UDP 通过，这两个样本也不能绕过网站和稳定性门槛。

建议的 HY2 路径是：云端认证实连 204 三轮 → 国内移动 UDP/QUIC 正向探测并记录协议验证程度 → 原有必过页面和 trace → 1 MB → 50 MB。无回应保持“国内未验证”，只在诊断报告保留；要将该方案作为生产入口门槛，仍需核实服务额度、回包校验能力和混淆节点覆盖。本文没有把这个候选方案接入每日发布。
