# 面向中国移动使用体验的节点筛选方案

更新时间：2026-10-10。运行约束：只用免费 GitHub Actions，每天北京时间 08:00 获取全部订阅、去重、检测，手机继续使用原订阅地址。本文区分当前已落实的筛选与下一步建议，建议部分尚未写入检测流程。

## 目标和依据

挑出入口能连、常用海外网站响应快、短时波动小、下载能力足够的节点。用户已经在本地对照过 TCPing 分类，确认其对当前中国移动环境有参考价值，因此国内 TCPing 作为入口必过条件保留。

分开看三个指标：国内 TCPing 判断入口连接；网站多轮请求判断响应与短时一致性；完整下载判断对应测试路径的吞吐量。不能用其中一个替代另外两个，也不把住宅类型、纯净度当作速度保证。TCPing 服务目前未公开探测点运营商，报告保持实际来源标注；本地对照的有效性来自用户反馈。

当前每日流程和订阅发布规则：

1. 获取全部来源并按连接参数去重，拒绝不支持的配置及控制字符损坏的节点。地区和原始速度标签不作依据。
2. HTTPS `generate_204` 独立测试三轮，三轮均符合 204 无正文才继续。
3. 国内 TCPing 必须明确连接成功；共享入口复用一次探测，不同凭据分别测试后续访问。明确失败与服务超时/限流分别记录；未验证节点不进入订阅。当前依赖 TCPing，因此纯 UDP 等不能提供有效 TCP 入口证明的节点也不发布。
4. 25 个海外页面各测试三轮；13个国内页面（移除抖音检测）和两个 trace 各一次。核对状态、域名、内容类型及站点标识，风控页不冒充正常页面。Amazon最多读取64 KB，其余最多16 KB，分别记录响应头和样本接收耗时，响应头超过 3 秒或样本超过 5 秒记为慢响应。trace 不替代首页，也不代表登录或对话成功。
5. Google、YouTube、ChatGPT、Gemini、GitHub、Wikipedia、Reddit、X、Instagram、Telegram、Discord、Facebook各三轮全部通过，并要求Claude trace单轮通过；Google和YouTube，中位响应不超过 1.5 秒、最慢不超过 3 秒、耗时极差不超过 1.5 秒。其余网站继续检测，但不能替代指定必过网站。
6. 12个页面三轮和Claude trace单轮均通过后再下载，完整1 MB下载通过才进入合格池。50 MB 下载仍只测试 1 MB 通过者，20 秒内完整收满才可进入高速组；未完成的下载不按收到的部分字节评估高速。
7. 综合、高速、非机房共用严格合格池。综合组按核心网站最差尾延迟、中位耗时、波动及其他网站耗时排序，再比较覆盖和下载；高速组在合格池中按完整 50 MB 速度排序；非机房组在合格池中按已确认独立出口选取。香港整体最多 30 个，非香港不限数量。
8. 新增第五组“🌏 台湾／新加坡”，仅按已确认出口 TW/SG 判断。用户授权允许网页稍慢：仍要求204三轮、国内TCP、指定12个页面各三轮访问、Claude trace单轮、1 MB下载全部通过；核心页面中位≤3秒、最慢≤5秒、极差≤3秒。Claude首页不检测；不允许其他网站或trace替代12个页面成功，不放行验证码/错误页/未测/出口矛盾；50 MB不是地区组必过条件。仅符合地区门槛的节点不进入综合、高速或非机房组。两地区不设数量限制；空组显示REJECT，不以失败节点补足。旧两站门槛曾入选新加坡1个、台湾0个；这不代表它们通过当前12个页面加Claude trace门槛，不能凭放宽耗时弥补Google访问及下载失败。
9. 不满足严格或地区门槛的节点不写入订阅的 `proxies` 或任何分组；报告保留其检测结果。每天全量获取和重新测量，恢复的节点仍可重新入选。专项修复只处理已有定义，不能把已删除凭据从报告中恢复；重新考察全部来源使用 `full`。

两类门槛均无合格节点、缺分片或配置校验失败时不覆盖原订阅，避免为了凑数量发布失败节点。如果只有地区组有合格节点，全局默认选择地区组。报告明确原数据时间，旧订阅保留不等于本轮重新验证通过。

## 下一步建议：测量分层，增加稳定性证据

以下是建议方案，尚未实施。先让用户用当前干净订阅对照，再决定阈值是否需要收紧；不因手机体验问题盲目增加几十个首页目标。

### 1. 核心路径优先，广度测试适度

保持所有来源都参加 204 和符合阶段条件的国内 TCP 筛选。通过后优先测 Google、YouTube 三轮；核心响应不合格便停止昂贵的后续检测。核心合格者再测其他海外站、trace 和下载。这样淘汰标准有针对性，减少无效请求；不限制全量来源抽样数量，也不回退到弱节点。

针对 YouTube 补充实际依赖路径：首页以外，核对当日首页中可验证的静态脚本与图片资源，分别记录成功和响应耗时。资源地址应从当日页面解析并验证域名，避免固定过期地址；不拿通用 204 当成全部资源通过，不用不经验证的随机 `googlevideo.com` 主机代表视频 CDN。静态资源能改善首页诊断，但仍不是完整视频播放测试。

ChatGPT、Gemini、GitHub 等保留逐站表现；Claude按用户授权只测trace：403、验证码、鉴权要求单独记录，不能一律推断线路断开。用户需要某平台时优先选择该平台真实页面响应合格的节点；仅 trace 通过不能证明平台功能可用。不为每个网站新增分组。

### 2. 快速重复与间隔复测分开

目前连续三轮用于发现短时超时和波动，不足以证明长期稳定。建议对首轮合格池再做一次仅含 Google、YouTube 和关键资源的间隔复测，距离第一次至少 30 秒；不重跑25站和50 MB。

建议每个核心首页累计六次样本，六次均通过才标本轮稳定；超过阈值或超时直接淘汰，不以补测成功抹掉失败。记录成功率、中位、最大耗时和极差；六个样本仍不称长期 P95。复测连接上限固定，并避免同节点下载与页面复测重叠，减少自己制造的慢响应。

### 3. 增加跨日记录，再调整排序

建议保留最近七天的节点标识与摘要，每个每日 full 在一天内只贡献一次历史样本。按真实成功率和数据新鲜度优先排序，再比较网页耗时、波动、下载。初步候选标准是最近三次完整日测至少两次合格；新节点不能因没有历史被假定优秀，也不因没有历史永远无法入选：当日所有门槛通过可先加入，但排在连续稳定节点之后。

当前国内 TCP 测试是单次。间隔复测时建议对最终合格池的独立 TCP 入口再测一次，支持“首测失败、复测成功”等独立分类；连续失败不得因204很快被放行。服务限流或异常属于证据不足，保留报告，不伪造节点故障。若服务不足以完成新增探测，先保留原一次门槛，报告明确未完成额外验证。

### 4. 下载作为能力门槛与排序辅助

50 MB 在 20 秒内完整完成，对应包含建连的平均速度至少约 20 Mbps。高速组当前已经满足这个条件。建议先对比综合组中132个节点与高速组122个节点的手机体验，判断另外10个只通过快测的节点是否值得保留。

若这些节点本地也明显偏慢，可把完整 50 MB 通过提升为综合组必过条件；若它们网页快、只是 Cloudflare 路径差，则保留综合组，降低带宽置信度。先用反馈验证这项取舍，不把单一 Cloudflare 路径的成绩等同所有网站带宽。1 MB含建连且过小，不能仅凭其瞬时速度宣布高带宽。

### 5. 最小手机校准，使用原订阅

不要求本地定时脚本、新订阅或额外分组。建议先选 8—12 个现有合格节点，覆盖前排与中排、不同地区、不同 TCP 入口耗时、机房与非机房，包含仅快测通过与完整50 MB通过的节点。

同一手机保持中国移动、相同规则模式，依次选择节点，测试相同的 YouTube 首页和 Google 页面；每节点三次，记录“能否打开、内容出现时间、偶发失败”，再在晚间重复一次。避免缓存掩盖差异，并同步记下节点短编号和选择时间；不用全球组的自动选择结果代替指定节点。

| 手机反馈 | 筛选调整方向 |
|---|---|
| TCPing通过、本地实际不通 | 检查入口样本一致性；将该节点列入有期限的本地失败记录，不能改写云端原结果 |
| 国内入口快、首页仍慢 | 核查关键资源及节点到网站的响应，不只收紧204阈值 |
| 首页快、完整下载弱 | 区分网页型与带宽型，不用一次小文件测速证明持续吞吐 |
| 云端排名与手机体验明显相反 | 用配对样本检验国内TCP耗时与手机结果的关系，再提高入口耗时权重，不直接把两段耗时相加当成手机实测 |
| 白天好、晚间差 | 补充七天和间隔记录；必要时增加一个云端晚间核心复测窗口，而非重复全量下载 |

这一步用于调阈值和权重。入口可达沿用已验证的 TCPing 逻辑，网站响应与下载作为后续独立筛选；最终用少量手机反馈校准先后顺序。待有配对样本，再确定哪些阈值真正提高本地成功率，避免人为给一个未经验证的综合分数。

## 测量边界与实现参考

当前响应头计时包含获取响应头之前的连接、跳转与等待；未来若增加 DNS/TCP/TLS/首字节的细分，应参考 [curl 官方计时字段](https://curl.se/docs/manpage.html#--write-out)，明确累计时间与分段耗时，不把代理本地连接计时误当国内入口耗时。现有实现使用 Requests，尚未提供这些细分字段。

下载地址依据 [Cloudflare 官方测速引擎](https://github.com/cloudflare/speedtest)。同时保留网站请求和下载测量，两种结果分别判断；不把第三方住宅与网段信誉标签替代性能测量。额外跨日、间隔、资源和手机反馈流程按上述建议逐项落地，当前已落实严格池、独立地区门槛与淘汰节点彻底移除。

每轮完整全量测量在Actions保存full-test-report存档7天，无合格候选时也可审阅完整测量。此时发布拒绝覆盖旧订阅，并明确旧配置尚未满足新门槛。
