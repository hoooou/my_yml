# Clash / v2rayN 节点优选与检测说明

每 6 小时（北京时间 05:00、11:00、17:00、23:00）用免费 GitHub Actions 获取公开订阅，去重后在云端检测，生成适用于 FlClash、Clash Meta / Mihomo 的完整配置。目标是入口可达、响应快、稳定且上下行良好；出口 IP 变化本身不作为淘汰理由。

建议 24 小时刷新一次，手动任务跑完可立即刷新。FlClash 需用规则模式并确保流量进入 VPN/TUN；Clash Verge 的应用设置或订阅脚本可能覆盖配置，排查时以核心实际加载的配置为准。

适用于已核对的 v2rayN 7.24.4：订阅分组里添加该地址、关闭订阅转换，更新后每个节点独立显示，可单独选择、编辑和测速。使用官方支持的 `v2rayn://` 原生格式（ConfigVersion=4），保留 HTTP、Trojan、VLESS 等节点的实际地址、端口、认证、TLS/SNI、WS、XHTTP 与 HTTP 伪装传输；不冒充 SOCKS、不包成 Custom。不能完整转换的协议或字段只从 v2rayN 订阅中略过（Clash 配置照常保留），名称与原因记在报告的 `v2rayn_skipped`。每轮与 Clash 订阅用同一批合格节点发布；原生订阅只带节点参数，不带 Clash 的分组、进程规则或内网 DNS。

### 链式配置（前置 → 美国落地）

```text
https://gcore.jsdelivr.net/gh/hoooou/my_yml@main/%E9%93%BE%E5%BC%8F%E9%85%8D%E7%BD%AE.yaml
https://cdn.jsdelivr.net/gh/hoooou/my_yml@main/%E9%93%BE%E5%BC%8F%E9%85%8D%E7%BD%AE.yaml
https://raw.githubusercontent.com/hoooou/my_yml/main/%E9%93%BE%E5%BC%8F%E9%85%8D%E7%BD%AE.yaml
```

与 `优选配置.yaml` 同源、独立发布，不影响原配置。区别只有一处：落地节点通过 `dialer-proxy` 挂到 `🌉 前置` 组。前置从同一轮池子里筛，不按地区：国内 TCP 能过的都进前置轨道，再由实测门槛决定去留。前置和落地节点都直接写在配置里，不用 proxy-provider——客户端拉不到 provider 时链式会整组空掉。另外有一批自己的订阅节点（名字保留订阅里的原样），由流水线每轮拉下来单独成组 `🛫 yieti`：组里第一项 `🛫 yieti 自动` 是 url-test，只放订阅里延迟最低的 15 个（5 分钟一轮、没在用时不探测），默认选中它，其余 400 多个节点留在组里手动强制选中；`🌉 前置` 组里只有两个选项：`🔄 自动前置`（走检测过的前置）和 `🛫 yieti`。客户端不需要再拉任何 provider，打开就是全部节点。订阅地址写在仓库里，token 是公开的，别外传。

| 前置条件 | 说明 |
|---|---|
| 国内 TCP 可达 | `xxapi` 探测点从国内发起，单次 TCP 成功 |
| 上行预检 | 前置自己的上传预检通过 |
| TLS 无异常 | 前置自己的 TLS 探测无异常 |
| 回国 / 出国 | 国内与海外目标都能连通 |

排序：已有的 5MB 下载速度（没有则用 1MB）→ 国内 TCP 延迟。没有前置或没有落地时不生成链式配置，`chain_enabled` 记 false、上一版保持不变；原订阅不受影响。

落地侧（`后置配置.yaml`）：预检、上行预检、1MB、5MB、必过站点、应用 TLS、100MB 单目标一轮全部通过（5MB 低于 4MiB/s 的节点不提交，直接排除），稳定性有记录时也要通过；只收 TCP 类型（hysteria2／tuic／wireguard 不收，前置转发不了 UDP），并排除 Cloudflare。名字按出口国家重新编号（`美国01|…`），地区组按前缀筛；美国拆成三组——`🇺🇸 美国节点` 收全部美国节点，`🏢 美国机房` 与 `🏠 美国住宅` 按名字第四段的 `机房`／`住宅` 标记细分，未知和移动网络只进美国节点组。

已知限制：链式必然增加延迟；前置只测自己这一段（回国、出国、TLS），不单独跑下载测速；`v2rayN.txt` 不挂链。

| 分组 | 条件与用途 |
|---|---|
| 🚀 全局选择 | 手动选择任一已发布节点（含免测节点）；默认综合优选 |
| ⭐ 综合优选 | 入口、逐站可达、应用 SSL 及 1MB 通过，持续稳定性 ≥90%；综合组取本轮 ≥99%（不足时取最高成功率档）且结束已恢复的节点，多轮历史不稳者不进 |
| 🚄 中速下载 | 合格池内完整通过 5MB 快测的节点，含台湾／新加坡地区池 |
| ⚡ 高速下载 | 综合合格池内 Cloudflare 100MB 完整通过，按该次速度排序 |
| 🏠 非机房 IP | 综合合格池内明确 hosting=false、没有出口矛盾；按独立出口 IP 去重 |
| 🌏 台湾／新加坡 | trace 确认 TW/SG；入口、必过网站/API、SSL、1MB 和稳定性仍须通过 |
| 🍓 小草莓（免测） | 用户指定订阅在最终生成时追加，保留原名；单独 select，不测速、不淘汰、不进各优选组 |

香港整体最多 30 个，非香港不限数量。中速／高速组保留所有满足条件的已入选节点，不另取前 30，组间可重叠、数量不能相加；空组显示 REJECT，不用失败节点补足。

小草莓是用户明确授权的免测例外，地址放在 Actions Secret `UNTESTED_SUBSCRIPTION_URL`，不写进仓库。只在全部筛选完成后追加 `proxies`，不接受来源自己的规则或 DNS；名称加 `🍓 ` 前缀，不伪造延迟、带宽、住宅或纯净度；获取失败时本轮不含免测节点，其余照常发布。

全局组用 select、默认综合优选；其他组 url-test，每 120 秒测一轮、3 秒超时、切换容差 100ms、不 lazy。只有单轮探测失败（节点真的不通）才立刻切走；当前节点只是变慢、没有慢出 100ms 就不换。

节点名称：`美国01|120ms|85Mbps|机房|纯净度99.2%`。延迟取实际请求中位数；带宽优先 100MB 实测，再用通过的 5MB 或 1MB。第四段按出口 IP 类型显示 `机房`／`住宅`／`移动网络`／`未知`：`机房` 是 hosting=true，`住宅` 要求 hosting=false 且运营商类型 isp，`移动网络` 是 is_mobile，其余一律 `未知`——未知不等于住宅，住宅也不保证快速或稳定。

## 当前筛选流程

八个免费 Actions 分片并行，探测阶段每片 100 并发、网站阶段收口到 16；同一节点按阶段顺序检测，不同节点处于不同阶段。网站、下载与持续稳定性跑在不同机器上，避免同一台测速机抢带宽。每天重新参测，不永久拉黑某协议或某地区。

| 顺序 | 环节 | 当前要求及失败影响 |
|---|---|---|
| 0 | 来源获取／去重／解析 | 读取 `聚合配置.yaml` 与 `节点来源.yaml`，按完整连接配置去重，不合并不同凭据或传输参数；剔除不支持的协议和含非法控制字符的节点 |
| 1 | 双 HTTPS 204 各三轮 | Google `connectivitycheck.gstatic.com/generate_204` 与 Cloudflare `cp.cloudflare.com/generate_204` 交替，各三次无正文 204、严格 TLS；两者全过才进入国内 TCP，节点名延迟仍取 Google |
| 2 | 国内入口 TCPing | 小小 API，一入口一次、共享入口去重；每片 30 请求/秒。明确连接失败淘汰，接口异常保持未验证；正式流程不凭云端 204 放行 |
| 3 | 3MB 上行预检 | `speed.cloudflare.com/__up?bytes=3000000`，随机合成 3,000,000 字节、6 秒预算、严格证书校验。速度不达标继续后面阶段，TLS 异常仍淘汰 |
| 4 | Cloudflare 1MB 快测 | `__down?bytes=1000000`，6 秒内完整接收，所有入选节点必过；下载很便宜，先按每片 100 并发跑掉，不过的不再跑网站和 TLS |
| 补充 | FAST API／Netflix CDN | 1MB 通过后取最多三个不同 CDN 主机，各下载 1MB、各 6 秒；普通失败只报告，明确证书错误淘汰 |
| 5 | Cloudflare 5MB 快测 | `__down?bytes=5000000`，10 秒内完整接收，每片最多 4 并发；不过的不再跑网站、TLS 和 100MB；通过但低于 4MiB/s 的不提交 100MB |
| 6 | 海外网页／API／trace | 26 个海外站点（含 ChatGPT API）各三轮，两个 trace 单轮；每节点最多 5 请求并发。必过目标见下文；任何网站／API／trace 出现 TLS 异常（含非必过）均淘汰 |
| 7 | 应用 SSL | chatgpt.com、android.chat.openai.com、auth.openai.com、cdn.oaistatic.com 各至少两次成功独立 TLS；单次 5 秒、TLS ≥1.2，信任链、域名、有效期必须正常 |
| 8 | Cloudflare 100MB | `__down?bytes=100000000`，20 秒内完整接收，带 Referer；5MB 通过、网站和应用 SSL 都过的节点才跑，通过才进高速组 |
| 9 | 最终上行及负载 | 复用 3MB 预检，再对 Cloudflare 上传 5MB 两轮、各 10 秒、间隔 20 秒；速度失败也完成两轮，TLS 异常仍淘汰 |
| 10 | 上传后 SSL | 四个应用域名再次各两轮严格 TLS |
| 并行 | 持续稳定性 | 国内 TCP 通过即独立观察，3MB 预检不阻挡；每轮随机等待 3～10 秒、不重叠，每片 16 个节点并发。主流程一结束就停止采样，不再补收尾轮；证据要求每节点至少 10 分钟窗口，最后一次采样不得早于主流程结束前 25 分钟 |
| 11 | 合并／分组／校验 | 核对同轮、分片与节点覆盖、各项原始证据；缺片、漏测、对照异常拒绝更新订阅，Mihomo 校验通过才发布 |

204、网站响应、trace、上下行与证书证据分别判断，不能相互替代。上行 6 秒含建连与响应，3MB 对应约 4Mbps 端到端下限；客户端完整提交且预期 HTTP 响应正常，不是逐字节服务器收据。下载要求 HTTP200、正确目标／类型／声明长度、无压缩无跳转及完整字节数；半截下载不算通过。小文件速度含握手和首字节等待，不是持续峰值带宽。

稳定性成功率 ≥90%，排名考虑成功率、最长连续失败、每站成功请求 P95／P99、四分位距和上下行表现；失败通过成功率单独处罚，不混入延迟分位数，少于 100 个成功样本不展示 P99。明确证书校验错误始终淘汰，不因偶尔恢复抹去。

### 网站、API 及访问限制

逐站必过（三轮至少两次认可可达，余下一次只能是普通连接失败）：Google、YouTube、ChatGPT、Gemini、GitHub、Wikipedia、Reddit、X、Instagram、Telegram、Discord、Facebook、ChatGPT API。Claude 首页不测，只要求 `claude.ai/cdn-cgi/trace`；ChatGPT trace 为 `chatgpt.com/cdn-cgi/trace`，首次普通连接失败允许复测一次且必须成功。

其他页面：Amazon、Bing、Cursor、Disney+、Hugging Face、Netflix、Perplexity、Spotify、Stack Overflow、Steam、TikTok、Twitch、WhatsApp，参与覆盖／质量和证书检查，单站失败不是独立淘汰条件。抖音和普通国产网页不参加逐节点测试；国产应用走 DIRECT。检测与分流共用 `site_catalog.py` 清单。

正常网页要求正确 HTTPS 主机、200、HTML 及站点特征；首响应预算 3 秒、正文采样总预算 5 秒，一般正文上限 16KiB，Amazon 64KiB，Reddit 401/403 读到 512KiB 以定位可见登录提示。使用桌面 Chrome 兼容请求头，不固定 Bot UA；普通跳转最多两次且限制到入口域名及 www／非 www。明确的 Cloudflare 人机验证在已测网页上认可可达（需预期主机与 `cf-mitigated: challenge` 等确认信号），Reddit 明确要求登录也认可可达；普通 403、`server=cloudflare` 或脚本里出现 captcha 都不足以放行。人机验证和登录提示不算正常页面速度。

ChatGPT API：`api.openai.com/compliance/cookie_requirements`，要求预期地址、HTTP200、JSON 且 `cookie_consent_required` 为布尔值、无实际 error；这个接口不是会话检测，缺少地区错误也不能直接算通过。

### FAST 补测

用公开浏览器 token 调 `api.fast.com/netflix/speedtest/v2`，urlCount=3，接口预算 5 秒、正文 ≤64KiB、禁止自动跳转；只接受 443 端口的 `*.nflxvideo.net` 与合法 `/speedtest` 基址。三个目标都完整下载 1MB 才记通过，记录地区、耗时、字节与 Mbps；普通失败不改变门槛，明确证书错误仍淘汰。

## 分流、内网 DNS 与 IP 标签

私有内网域名优先 DIRECT，`nameserver-policy` 指向内网 DNS 并排除 fake-ip（域名与 DNS 地址只写在 `scripts/routing.py`）。开启 `direct-nameserver-follow-policy`，防止直连解析改用公共 DNS；使用精确域名后缀，不依赖模糊关键词。

匹配顺序：内网／局域网直连 → 广告规则 → 个人进程例外 → 应用进程 → 应用域名兜底 → 明确海外服务 → 国内服务 → 个人域名例外及维护规则集 → 中国 IP 直连 → 未匹配走全局。

| 路由 | 应用 |
|---|---|
| 指定直连 | 微信、微博、美团／大众点评、拼多多、京东、高德地图、企业微信、向日葵、腾讯会议 |
| 补充直连 | QQ／TIM、支付宝、淘宝、哔哩哔哩、抖音、网易云音乐、小红书 |
| 指定代理 | X／Twitter、Google Play、YouTube、Threads |
| 补充代理 | Telegram、Discord、Instagram、ChatGPT、Claude、Gemini、Cursor |

`find-process-mode: strict` 按需识别：Android 用完整包名，macOS／Windows 用实际可执行名称。浏览器、Python、Node、Git 和通用 Helper 不整进程固定路由；未识别时回退域名规则。进程名称采用人工审核快照，不整体导入厂商前缀或被注释条目。

住宅／纯净度优先来自 ipapi.is，密钥放在 Actions Secret `IPAPI_IS_KEY`。按独立出口去重查询，每轮预算 900 个 IP。没配密钥、密钥被拒（401／403／429）或个别 IP 查不出来时，自动改用免费的 ip-api.com 批量查询兜底：不需要密钥，一次最多 100 个 IP、15 次／分钟，返回 hosting／proxy／mobile 三个布尔值——hosting=true 判机房，mobile=true 判移动网络，三个都为 false 判住宅候选。兜底源没有滥用比例，所以这些节点显示“纯净度未知”，不补造数字。查到的结果按出口 IP 缓存在仓库里的 `IP归属缓存.json`，7 天内同一个 IP 不再重复查询，省下接口额度。纯净度 = 100 ×（1 − company.abuser_score 的有效网段比例），不是账号安全概率；无 hosting 证据不推断住宅。
